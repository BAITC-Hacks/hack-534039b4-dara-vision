# HackAlem Track 04: tariff campaign agent

An offline `Agent.act(env)` selects 1–10 tariff campaigns from public customer,
tariff and channel data. It runs sequential pilots, uses their feedback, and
keeps pilot and final contacts within the same resource limits. The included
`submission.csv` is generated by the organizers' `make_submission.py`.

## Setup and run

Python 3.11+ is required. From this repository directory:

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python -m pytest -q
python local_eval.py --runs 10
python make_submission.py
python scripts/evaluate.py --start 0 --count 10 --output reports/development.md
```

Evaluation and submission generation run offline after installation. The
agent resolves optional migration history relative to its own source file;
it falls back to profile and tariff data if that history is unavailable.
`scripts/evaluate.py` compares the agent with the unmodified official template
on paired seeds and writes Markdown and JSON reports. For a single verbose
official score, run `python local_eval.py`.

## Five-minute demo

From the repository directory, after setup:

```bash
python local_eval.py
python scripts/evaluate.py --start 0 --count 10 --output reports/development.md
python make_submission.py
sha256sum submission.csv
```

The first command shows the official mock score, pilot count, remaining budget,
and remaining contacts for seed 42. Open `reports/development.md` to see paired
seed results and a trace excerpt: `pilot_observed` records feedback,
`selection_updated` records the updated reserve, and `final_selected` records
the resulting campaigns. The generator uses the official fixed seed 42. Run it
twice to check that the CSV hash is unchanged; the committed file's SHA-256 is
`79450c91f9d1ab68e249a8ed0fa1ef6908b00df9f406b8108f38e4d7625669ad`.

The frozen policy's reserved mock evaluation is in `reports/reserved.md`
(seeds 100–119). It records median net 3,421,236, median paired improvement
3,865,759, zero negative runs, and zero reported violations. These figures
describe the supplied synthetic mock only; do not use them as a prediction of
the hidden judge or a real marketing campaign.

## Method

The agent partitions the audience into nonoverlapping, representable tariff ×
ARPU cells, splitting an oversized cell by data and then call segment. Migration
history orders possible targets but is observational and does not decide the
final plan. The agent pilots feasible cell, target and channel combinations,
updates a size weighted feedback estimate after every pilot, and selects
tested campaigns by estimated net value. A resource reserve keeps at least
one tested final campaign possible. Pilot spending is capped at 25% of the
initial budget; paid call pilots use smaller samples. An all negative estimate
triggers a least loss tested campaign to satisfy the competition contract,
with `emergency` recorded in `Agent.trace`.

This is a deterministic heuristic given identical input and pilot feedback.
Feedback shrinkage toward zero is not a calibrated confidence interval. The
official mock uses synthetic effects that differ from judging effects, so its
positive score does not establish production ROI or effectiveness on another
population. Pilot costs and contacts are charged; overlapping pilot and final
audiences are scored only by the official evaluator.

## Package and attribution

Official files are kept byte for byte from the participant ZIP. See
[`provenance.json`](provenance.json) and [`THIRD_PARTY.md`](THIRD_PARTY.md).
The required output fields are `campaign_name`, the four optional `filter_*`
fields, `target_tariff`, and `channel`. The agent reads no hidden evaluator
state, uses no network or LLM, and sends no messages to subscribers.
